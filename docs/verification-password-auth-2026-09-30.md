# 이메일/비밀번호 인증 추가 검증

## 비밀번호 최소 길이 조정 (후속)

- 가입·변경·운영자 재설정 및 앱 안내를 8~128자로 통일했다.
- 기존 비밀번호/해시/세션은 변경하지 않으며 DB 마이그레이션이 필요하지 않다.
- 문자열을 자르거나 정규화하지 않는다. 앱도 서버와 같은 Unicode scalar 기준으로 센다.
- 경계값 7/8/128/129자, 한글, 결합 문자를 검사했다. 인증/운영자 테스트 18개 통과.
- 서버 전체 테스트 54개 통과, 환경 의존 5개 제외. 변경 파일 Ruff 검사 통과.
- 로컬 서버 재시작 후 ready 및 OpenAPI의 minLength=8/maxLength=128을 확인했다.
- 앱 release 빌드·패키지 회귀 검사 후 설치/재실행 및 코드 서명·바이너리 일치를 확인했다.
- 이전 설치본은 작업 루트 reports/PokePackBar-before-password-length-20260930.zip으로 백업했다.
- 이는 사설 서버의 사용성 선택이며 MFA 없는 공개 서비스의 보안 권고 충족을 의미하지 않는다.

## 변경 범위

- Google OAuth 대신 이메일/비밀번호 가입·로그인, 기기별 Bearer 세션 도입.
- UUID만으로 게임 자원 접근 불가. 세션으로 계정을 결정하고 기기/선택적 계정 헤더 대조.
- Argon2id 비밀번호 해시, 서버 세션 원문 미보관, 앱 세션은 Keychain에 저장.
- 로그인 시도 제한, 7일 만료, 현재/전체 로그아웃, 비밀번호 변경·운영자 재설정.
- 기존 UUID 계정은 운영자 일회용 코드로 가입 시 연결. 자원/로그/적립 기록은 보존.
- 게임 규칙과 신뢰된 토큰 수집 방식은 변경하지 않음.
- 이메일은 수신 인증하지 않는 로그인 ID. 메일 발송/복구/MFA는 포함하지 않음.

## 실행 결과

- 서버 전체 **40 passed**: 실제 Swift 엔진 통합 포함, Ruff 통과.
- 인증 해시/계정 격리/기기 바인딩/세션 만료·폐기/재로그인/시도 제한 검사 통과.
- 가입 경쟁, 일회용 연결 코드 소비·만료·재사용 거절, 기존 자원 보존 검사 통과.
- 인증 후 대기 중 폐기된 세션이 쓰기 트랜잭션에서 다시 거절되는지 검사 통과.
- 비밀번호 검증 오류에 입력 원문이 반사되지 않는지 검사 통과.
- Alembic upgrade/downgrade/upgrade와 기존 지갑을 넣은 0002 → 0003 보존 검사 통과.
- Swift release 빌드와 실제 배포 번들 양쪽의 네이티브 HTTP 검사 통과:
  가입/로그인, 두 기기 자원 동기화, UUID-only 401, 구매·개봉, 응답 유실,
  로그아웃 후 요청 보존, 재로그인 후 같은 결과 복구, revision 충돌, 전체 로그아웃.
- 네이티브 통합 검사는 테스트 DB와 메모리 세션을 사용하며 개인 Keychain/세이브 미접근.
- 앱 패키징의 기존 한국어/시세/리소스/홀로 계약/대량 개봉 회귀 검사 통과.
- 새 앱 서명 검증 및 설치 전후 실행 파일 SHA-256 일치 확인.

## 로컬 적용

- 기존 DB 백업: `.data/pre-password-auth-20260930.sqlite3` (Git 제외).
- 실행 DB는 0003 적용, `/ready` 200, UUID-only 게임 요청 401 확인.
- 운영 DB 계정 0개 유지. 사용자의 계정을 대신 만들거나 개인 세이브를 가져오지 않음.
- 규칙 엔진 스냅샷: `.data/rules-password-auth` (Git 제외).
- 설치: `/Applications/PokePackBar.app`, 0.11.12 로컬 커스텀 빌드.
- 이전 앱은 `~/.Trash/PokePackBar-before-password-auth-20260930.app`으로 이동하여 복구 가능.
- 커밋/push/PR/외부 서버 배포는 하지 않음.

## 검증 경계

- 설정 화면을 직접 클릭하는 수동 검사와 실제 두 대의 Mac 검사는 별도.
- 사용자 Keychain 저장/재시작 경로는 소스와 빌드를 확인했으며, 개인 계정을 생성해
  로그인하거나 Keychain을 읽는 방식의 실사용 검사는 하지 않음.
- 실제 이메일 전달·소유권 검증은 구현하지 않았으므로 검증 대상 아님.
- TestClient의 httpx 관련 상위 라이브러리 deprecation 경고 1건이 남음.
- localhost 실행용. 외부 공개 서비스 전 이메일 소유 확인/복구 정책,
  프록시·TLS·운영 제한과 백업/로그 보관을 별도 설계해야 함.
