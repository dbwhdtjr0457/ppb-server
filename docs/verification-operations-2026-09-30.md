# 계정·운영 및 설정 UI 개선 검증 — 2026-09-30

## 적용 범위

- 작은 메뉴바 설정을 일반 / 표시 / 데이터 / 고급으로 구분했다. 기존 기능을 제거하지 않고 로그인·기기·보안·서버 상태를 크기 조절 가능한 별도 ‘계정 및 서버’ 창으로 이동했다.
- 계정 창은 연결 / 보안 / 기기 / 서버 상태로 구분한다. 서버 주소와 진단 정보는 접힌 상세 영역에 둔다. 창을 닫으면 해당 뷰를 폐기해 입력 비밀번호·표시 중인 복구 코드를 유지하지 않는다.
- 기기 이름 변경·개별 세션 폐기, 비밀번호 확인 후 일회용 복구 코드 발급·재발급, 코드로 비밀번호 재설정을 추가했다. 코드 원문은 DB에 저장하지 않으며 사용·재발급·비밀번호 변경 시 무효화한다. 재설정 시 모든 세션을 폐기하고 자동 로그인하지 않는다.
- 일일 SQLite 백업, 별도 임시 DB 복원 검사, 성공한 백업 14개 보관을 추가했다. 실패하면 이전 백업을 유지하고 한 시간 후 재시도한다. 서버 상태 화면에 백업·시세·만료 작업의 성공 시각과 오류를 표시한다.
- 1,000팩 초과 개봉을 서버 작업으로 기록한다. 각 1,000팩 단위 자원 변경·진행률·재시도 영수증을 한 트랜잭션에 저장한다. 온라인 창 ‘작업’에서 남은 개봉을 이어가거나 취소할 수 있다. 창 닫기/중지는 현재 묶음 이후 다음 요청을 멈춘다.
- 만료 대상이 없는 상태 조회에서는 SQLite 쓰기 잠금을 얻지 않도록 개선했다. 최근 규칙 실행·잠금 대기의 P50/P95를 프로세스별로 제공한다.
- 선택적으로 한 기기만 토큰 적립을 담당하도록 설정할 수 있다. 기본 다중 기기 합산은 그대로 유지했다. 정책 변경 후 첫 보고는 기준값만 저장하고 중복 적립하지 않는다. 실제 사용량의 진위 검증을 뜻하지 않는다.

## 검증 결과

- 실제 Swift 규칙 실행 파일을 지정한 서버 전체 테스트: **73 passed**, skip 없음. 기존 Starlette/httpx 사용 중단 예고 경고 1건.
- Ruff 및 양쪽 저장소 `git diff --check` 통과. 기존 미커밋 변경은 유지했다.
- 릴리스 앱 빌드·리소스 검사·코드 서명 검증 통과.
- 네이티브 API 검사: 두 기기 로그인, 친구 승인, 판형 예약, 교환, 마켓, 잔액 중복 차감 방지, 응답 유실/재로그인 복구 통과.
- 실제 1,001팩 작업을 1,000+1로 개봉하고 마지막 응답을 유실시킨 후 클라이언트를 재생성해 복구했다. 작업 완료 수량·자원·미확인 요청 정리를 검증했다.
- 위 검사에서 발견한 JSON 결과 저장 문제를 수정했다. SQLAlchemy에 결과 변경을 명시적으로 알리도록 하여 개봉 작업 진행률이 원래 영수증에 저장되고 재시도 시 같은 결과를 반환한다.
- 설정 4화면, 계정 9화면을 네이티브 렌더링했다. 주요 화면을 좁은 폭·넓은 폭과 밝은/어두운 모드로 확인했다. 온라인 창 6탭을 두 크기로 렌더링했다. 계정 창 및 온라인 창 닫기·다시 열기를 검사했다.
- `minimumWidth`는 SwiftUI 고유 크기 측정값이지 화면 잘림 판정값이 아니다. 주요 화면 캡처를 직접 확인했으며 화면 아래 콘텐츠는 스크롤한다. 실사용자 계정의 입력·키체인 조작은 하지 않았고 테스트 계정·격리 DB만 사용했다.

## 한계와 후속 범위

- 같은 디스크의 백업은 디스크 고장 대비가 아니다. 별도 저장소 복사와 실제 운영 복원은 별도 절차로 진행한다. 자동 복원은 하지 않는다.
- 코드 복구는 이메일 소유 확인이나 MFA가 아니다. 코드를 미리 안전한 곳에 보관해야 한다. 발급 응답을 잃으면 비밀번호로 재발급한다.
- 적립 담당 기기 지정은 동일 사용량의 중복 보고 위험을 줄이지만 클라이언트가 보고한 사용량을 증명하지 않는다. 기존 사설 서버 신뢰 모델이 유지된다.
- 재개 가능한 대량 작업은 **개봉**에 적용했다. 구매·판매 작업 큐, 상주 Swift 엔진, 공개 서비스 수준의 부정 사용 방지는 구현하지 않았다.
- 작업은 서버에서 무인으로 계속 개봉하지 않는다. 앱에서 다음 묶음을 요청해야 진행한다. 다른 기기와 동시에 요청하면 버전 충돌을 확인하고 다시 조회해야 한다.
- 기존 게임 규칙과 홀로 렌더러는 이번 UI 정리에서 변경하지 않았다. 로컬 redesign 스킬의 기존 기능 보존·화면 분리 기준을 참고했으며, 제거된 ui-craft 패키지는 재설치하지 않았다.
